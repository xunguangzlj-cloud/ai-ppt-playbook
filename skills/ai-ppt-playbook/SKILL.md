# AI 时代 PPT 制作手册

让每一页成为听众理解工作的一步。以论证、设计系统、交付能力和审核回环组织工作。项目文档研究与实际运行验证分别记录；上游宣传、星数和单个案例不能证明普遍质量。2026-10-06的扩展研究覆盖17个项目，版本与阅读范围见仓库的扩展调研记录。

## 0. 先确定使用方式

从用户要求和附件中确认：受众、用途、总页数、时限、模板、是否需要独立阅读。已明确的信息不要重复问。缺少会实质改变成果的信息时简洁询问，同时完成材料整理；可用合理默认的事项，说明假设后直接推进——不要让提问阻塞工作。

- **现场讲述型**：观众听讲为主。屏幕保留观点、关系与证据，解释推导放讲者备注。
- **提交阅读型**：读者不依赖讲者。正文保留背景、方法、条件、来源与局限，理解结论所需的内容不能只躺在备注里。
- **兼用型**：先保证独立阅读和事实完整，再用章节层级、小结与附录分配信息。

用户指定的模板、评分要求、字数、页数优先。N 页含封面与结尾页，除非用户明确另算；不要擅自加页。用户要求与模板约束并存时，先检查能否同时满足（如"感谢页配正文"），只有真实冲突才提出澄清——不能替用户决定删掉哪项要求。

## 1. 五阶段流水线

```
① 澄清 → ② 论证与分镜 → ③ 风格与样张 → ④ 生成 → ⑤ 自检交付
```

**① 澄清**：用"沟通契约"六问替代模糊需求——受众是谁/意图是什么/什么可观察变化算成功（audience_outcome）/核心信息是什么/讲述还是阅读/交付后要支持什么（artifact_afterlife）。详见 [storyboard-and-gates.md](references/storyboard-and-gates.md)。

**② 论证与分镜**：从材料建立论证链——问题为何值得解决 → 方法如何回应 → 结果如何检验 → 结论推到哪里。结论缺证据时缩小表述或明示缺口，不能用版式掩盖。每页写一句"看完应理解什么"，在用户允许的范围内合并冗余内容。仅优化排版时保留原文、页序和备注；不得自行删页或改观点。

**③ 风格与样张**：已有模板或明确风格时直接沿用。开放设计且取舍会显著影响成果时，可提供少量真正不同的方向。用代表性内容页检查真实文本、图表和素材能否放下；用户要求先审样张时等待其确认，其余情况把样张作为内部验证后继续完成。

**④ 生成**：先核对宿主要求、可用引擎和导出能力，再按任务选型。记录样张所用方法与共享设计参数，保持跨页一致；是否并行依任务规模和环境权限决定，不默认创建子代理。

**⑤ 自检交付**：代码级检查（溢出/重叠/占位符残留）→ 渲染成图逐页目检（字形/换行/遮挡/越界）→ 修复后复验。只有实际验证过的能力才能声称。

## 2. 以最终文件能力选型

| | 可编辑原生轨 | 整页生图轨 |
|---|---|---|
| 适用 | 需要修改文字/数据、模板继承、证据精度的任务 | 用户接受页面为图片的视觉展示 |
| 中间表示 | 大纲→元素级结构（代码生成或语义标记） | 逐页提示词→整页图→组装 PPTX |
| 工具 | 宿主允许的原生生成、模板编辑或经验证的转换引擎 | 生图模型 + 组装脚本 |
| 可编辑性 | 按对象核验：文字可改不等于图表数据可改，也不等于母版继承完整 | 图片中的元素不能直接编辑；重建分层必须另行校对 |
| 成本 | 取决于材料、布局、引擎和返修次数，先小样测量 | 取决于分辨率、调用和重试次数 |

还可以混用原生文字/图表与照片或插图。答辩场景本身不能决定采用整页生图。Markdown、HTML和SVG是中间表示，不自动决定PPTX的可编辑性。路线与版本边界见 [routes.md](references/routes.md)。

## 3. 设计与证据底线

统一背景、主色、强调色与字体层级，布局表达实际关系。避免没有信息作用的装饰及机械重复，但不把审美偏好当成普遍禁令。中文换行、字体和段落应在导出的文件中验证；原生图表还需校验数据和尺度。制作时读 [设计系统](references/design-system.md)，数据页另读 [数据图表](references/data-and-charts.md)。模板编辑读 [模板保留](references/template-preservation.md)。

## 4. 交付诚实纪律

- 文字、表格、要求可编辑的图表保持原生对象；**不能把大纲、HTML 或整页图片冒充可编辑 PPTX**。
- 动画、特殊字体、外部链接先验证工具能力；不能实现就明说限制，用静态方式承接。
- 只有实际打开/渲染检查过的，才能声称验证过；渲染检查与结构检查各自不能互相替代。
- 修改源文件、共享字体或素材后，重新导出并核验受影响页面；以最终交付文件的哈希关联检查记录，避免审的是旧稿、发的是新稿。
- 可运行本技能的 `scripts/audit_pptx.py` 检查包内引用、页数及原生对象；仅改设计时用其保留对照选项。该脚本不能证明没有视觉溢出，也不能代替PowerPoint、WPS或LibreOffice的实际渲染。
- 不承诺"包过""拿奖"或控制评委提问；交付默认不附校验日志与制作过程。

## 6. 与内容层技能的分工

本技能负责**制作与设计**（怎么做得专业）；`ppt-evidence-design` 类技能负责**内容决策**（论证链是否成立、证据是否真实、来源是否可溯）。两者同时可用时：内容技能定"每页说什么、凭什么"，本技能定"长什么样、怎么生成与交付"。
