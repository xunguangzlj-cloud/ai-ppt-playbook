# 路线选择：中间表示与最终能力分开判断

先读宿主当前的实现要求。宿主指定引擎时使用指定引擎，外部项目只提供方法参照；不要因某个库流行就覆盖环境约束。此表记录2026-10-06查到的能力，实际命令还需核对已安装版本。

| 任务 | 可考虑路线 | 必须检查的边界 |
|---|---|---|
| 原稿只改排版 | 原生PPTX编辑或局部OOXML修改 | 保留原文、备注、图片与未修改对象；重导入可能归一化源结构 |
| 使用已有模板换内容 | 克隆与字段填充，或经验证的模板引擎 | 页面、母版、版式、主题与资源引用须共同处理 |
| 新建可编辑PPTX | 宿主原生工具、PptxGenJS、语义SVG编译 | 各对象的编辑能力、画布单位与实际渲染 |
| 有HTML模板和结构字段 | Presenton、PPTAgent、PPTist或受支持转换器 | 网页可编辑不等于导出的图表数据可编辑；特殊CSS可能栅格化 |
| Markdown为主要内容源 | Quarto/Pandoc、Marp、Slidev | 不同引擎和导出模式的PPTX能力不同，不能统一归为图片或原生 |
| 用户接受图片页面 | 整页生图或网页截图组装 | 明示文字、图表不可直接编辑；严格原图和事实标签不以重绘替代 |
| 原生文字搭配插图 | 混合路线 | 分别声明哪些对象可编辑、哪些仍为图片 |

## 已核对的导出差异

- **Slidev**：普通`--format pptx`输出图片页面并传递备注；新增`--format pptx-editable`重建文字和基本形状。公式、SVG、画布和部分CSS仍为图片，个别页还可能整体退回图片。检查逐页结果和转换报告；点击步骤可能扩展页数，严格N页时核对`--with-clicks false`与实得页数。
- **Marp CLI**：普通`--pptx`为图片页面；实验性`--pptx-editable`依赖浏览器与LibreOffice，外观保真较低且不支持讲者备注。需要备注或复杂主题时，不能只凭扩展名通过验收。
- **Quarto/Pandoc**：可用`reference-doc`导出PowerPoint；参考文件要有匹配的具名版式。缺版式会回退到默认模板并提示，不能把成功导出当成模板完整继承。
- **PptxGenJS**：适合新建原生文字、形状、表格和图表；不能据此承诺无损导入已有复杂PPTX。
- **pptx-automizer**：适合模板页和对象复用，写出时才执行排队的修改。母版/版式中的复杂内容存在限制；先用真实模板小样验证。其246星单列为专业补充，不称高星项目。
- **PPTAgent**：当前skill使用HTML创作、渲染审查和可编辑转换；不能只沿用旧论文的plan-edit描述推断现版本行为。
- **整页图片转可编辑**：擦背景与重新分层是一种重建办法，不是恢复原始结构。OCR文本、数值、连线、字体和图层均需校对。

## 样张与方法记录

代表性内容页应包含最容易失败的元素，如长中文标题、原生图表或严格原图。样张验证的是能力与布局，不一定需要用户再审批。已有样式或用户授权直接制作时，验证后继续；用户明确要求先审样张时等待。

记录引擎版本、画布、字体、素材身份、导出模式和检验方法即可。换工具时复验样张；如果新方案仍满足原有要求，可以继续并说明选择。只有会改变已明确的交付能力、成本或素材保留范围时才需用户选择。

不把约1万token/页、固定保真百分比或某种路线的“视觉上限”作为普遍预算。先对当前任务做小样，记录实际耗时与缺陷。
