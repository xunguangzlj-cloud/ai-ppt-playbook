# 双轨选型与六种架构模式

## 1. 六种架构模式（行业验证）

| 模式 | 代表 | 中间表示 | 可编辑性 | 视觉上限 | 成本 |
|---|---|---|---|---|---|
| A. SVG/语义标记→原生 | ppt-master | SVG + data-* 语义标记 | ★★★ 原生形状/图表 | ★★★ | 中 |
| B. HTML模板+字段填充 | presenton / dashi | HTML+Tailwind、版式+文案字段 | ★★★ | ★★（受模板限） | 低-中 |
| C. 整页生图 | banana-slides / codex-ppt-skill | 逐页提示词→整页图 | ✗（需二次转换） | ★★★ | 高 |
| D. JSON直生+编辑器底座 | PPTist、豆包 | 结构化 JSON | ★★★ | ★★ | 低 |
| E. Markdown 渲染 | marp / slidev | Markdown | 源码级 | ★★ | 最低 |
| F. plan-edit 编辑法 | PPTAgent | 参考稿+编辑操作 | ★★★ | ★★★ | 中 |

要点：
- 模式 A 的核心洞察：**AI 生成语义标记的 SVG/HTML，编译为 PowerPoint 原生对象**（形状带调节手柄、数据绑定的原生图表、真实母版继承链）。原则是"元数据严格可加性"——删掉标记后浏览器渲染不变，标记仅供编译器用。"可编辑只是及格线，原生才是差异化。"
- 模式 B 的关键数据结构：**页面 = 版式 + 文案字段**，让 AI 能读、改、校验；刻意限制自定义样式（"稳定的产出比自由的选色更重要"）。
- 模式 D 的约束设计：JSON schema 配三重白名单（HTML 标签/字体/path 命令），画布固定、元素数组序即层级——白名单是对抗 LLM 幻觉最有效的手段。
- 模式 C 的可编辑导出是 Beta 级难题（"擦底板+重分层"），见 [image-and-diagram.md](image-and-diagram.md)。

## 2. 选型决策

先问三个问题：交付后要不要二次编辑？（要→A/B/D/F；不要→C/E）视觉上限要求多高？（极高→C 或 A）预算多少？（约 1 万 token/页 vs 每页一张图）。

**一开始就选对轨**：图片式→可编辑的互转有损且昂贵；宁可前期多问一句用途。

工具映射（可编辑轨）：pptxgenjs（Node，坐标英寸，注意 LAYOUT_WIDE、hex 不带 #、透明度用 opacity 属性、bullet/阴影选项用工厂函数防对象突变）；python-pptx（文本替换/结构编辑首选）；raw OOXML（动画/母版等库触不到的层）。

## 3. 样张契约（生图轨尤其重要）

1. 大纲确认后，生成**恰好一页**代表性样张（优先内容页），不全量生成。
2. 样张直接存为正式文件名（如 `slide_08.png`）——批准后它就是那一页；不造 `sample.png`。
3. 批准后记录 `生成方法`（后端/工具/模式/模型/参数/提示词来源/样张路径）写入项目 spec，所有后续页与子代理继承同一方法。
4. 生图后端固定：中途不许因"方便"换后端；后端不可用时**报 blocker，不降级**。

## 4. 图片式 → 可编辑（擦底板+重分层）

整页生图轨的"可编辑导出"可行路径：

1. 对渲染好的整页图发擦除提示词：移除全部文字/插画/图表，**保持背景设计完整**（渐变、纹理、色块），被遮挡区域智能填补，"像被移除的元素从未出现过"；输出尺寸风格与原图完全一致。支持 0-1 归一化 bbox 列表定向移除（带 element_type）。
2. 在干净底板上重新叠加原生文本框/图形/表格——文字回到可编辑状态。
3. 局部修改用"原页面描述+编辑指令+用户框选区域"的组合提示词，约束"维持原有文字内容和设计风格，只按指令修改"。

局限要诚实：精确抠图分层仍不完美，重要交付优先选可编辑轨。
